# TTS Audio Generation

**Files:** `src/services/tts/TTSAudioGenerator.ts`, `src/services/tts/MicrosoftSpeechService.ts`, `src/services/tts/TTSCacheManager.ts`
**Last Updated:** March 30, 2026

---

## Overview

`TTSAudioGenerator` is a static factory that turns text into a local audio file path. It abstracts engine selection, caching, and fallback so that callers (`TTSAudioPreloader`) never need to know which engine is active.

---

## TTSAudioGenerator

**File:** `src/services/tts/TTSAudioGenerator.ts`

### Interface

```typescript
static async generateAudio(
  text: string,
  settings: VoiceSettings,
  options: GenerateOptions = {}
): Promise<GenerationResult>

interface VoiceSettings {
  voice: string;
  pitch?: number;
  rate?: number;
  engine: 'expo' | 'microsoft';
}

interface GenerateOptions {
  timeout?: number;
  forceRegenerate?: boolean;
  fallbackToExpo?: boolean;  // default: true
}

interface GenerationResult {
  uri: string;        // Local file path to audio
  cached: boolean;
  engine: 'expo' | 'microsoft';  // Actual engine used (may differ if fallback)
  duration?: number;  // Generation wall-clock time in ms
}
```

### Generation Logic

```
generateAudio(text, settings, options)
  ↓
1. Check TTSCacheManager (unless forceRegenerate)
     cache hit → return cached uri immediately
  ↓
2. Generate new audio
     settings.engine === 'microsoft'
       → generateWithMicrosoft()
           on error AND fallbackToExpo !== false
             → generateWithExpo()
     settings.engine === 'expo'
       → generateWithExpo()
  ↓
3. Store result in TTSCacheManager
  ↓
4. Return GenerationResult
```

### Cache Key

Cache keys are generated by `TTSCacheManager.generateKey(text, settings)`, which hashes text + voice + engine + pitch + rate. Same text with different voice settings produces different cache entries.

## Engine 1: NativeExpoSpeech (Device TTS)

**Spec:** `specs/NativeExpoSpeech.ts`
**Implementation:** `android/app/src/main/java/.../NativeExpoSpeech.kt`

`NativeExpoSpeech` is a Turbo Module that wraps Android's `TextToSpeech` engine to **write audio directly to a file** (instead of playing through speakers). This is distinct from the old `expo-speech` package which could only play.

**Key method:**
```typescript
NativeExpoSpeech.generateAudioFile(
  text: string,
  voice: string,
  pitch: number,
  rate: number,
  outputPath: string
): Promise<void>
```

The output is a `.wav` file at `outputPath`. `TTSAudioGenerator` then stores this in the cache.

**Advantages:**
- Works offline
- No cost
- Available on any Android device
- Voice quality depends on device TTS engine (Google TTS recommended)

## Engine 2: MicrosoftSpeechService (Azure Cloud TTS)

**File:** `src/services/tts/MicrosoftSpeechService.ts`

### Initialization

```typescript
microsoftSpeechService.initialize({
  subscriptionKey: string,
  region: string,           // e.g., 'eastus'
  voice?: string,           // default voice
})
```

Credentials come from MMKV key `INTEGRATION_SETTINGS` → `microsoftSpeech.subscriptionKey` / `region`.

### Audio Generation

```typescript
async generateAudio(text: string, settings: VoiceSettings): Promise<string>
// Returns: local file path to downloaded MP3
```

**Internal flow:**
1. Get access token from `https://{region}.cognitiveservices.azure.com/sts/v1.0/issueToken`
   - Token cached for 9 minutes (expires at 10)
2. Build SSML:
   ```xml
   <speak version="1.0" xmlns="..." xml:lang="en-US">
     <voice name="{voice}">
       <prosody pitch="{pitch}%" rate="{rate}">
         {escaped text}
       </prosody>
     </voice>
   </speak>
   ```
   - `pitch`: `(value - 1) * 50` → percentage string (`"0%"` = normal)
   - `rate`: decimal string (`"1.0"` = normal)
3. `POST https://{region}.tts.speech.microsoft.com/cognitiveservices/v1`
   - Headers: `Ocp-Apim-Subscription-Key`, `X-Microsoft-OutputFormat: audio-16khz-128kbitrate-mono-mp3`
4. Receive ArrayBuffer → write to temp file in `FileSystem.cacheDirectory`
5. Return file path

### Voice Enumeration

```typescript
async getVoices(locale?: string): Promise<MicrosoftVoice[]>
// GET https://{region}.tts.speech.microsoft.com/cognitiveservices/voices/list
```

Voices are displayed in Settings → Reader → TTS tab when Microsoft engine is selected.

### Credential Validation

```typescript
async validateCredentials(key: string, region: string): Promise<boolean>
```

Used in Settings → Integrations to verify credentials before saving.

### Error & Fallback

If `microsoftSpeechService.generateAudio()` throws, `TTSAudioGenerator` automatically falls back to `NativeExpoSpeech` (unless `fallbackToExpo: false` was passed). The `GenerationResult.engine` field reflects which engine was actually used.

## TTSCacheManager (LRU Cache)

**File:** `src/services/tts/TTSCacheManager.ts`

### Purpose

Avoids regenerating audio for text that's already been synthesized recently. Especially important for re-reads and chapter navigation.

### Properties

| Property | Value |
|---|---|
| Storage backend | `expo-file-system` (NOT MMKV — audio files are too large) |
| Cache directory | `FileSystem.cacheDirectory + 'tts/cache/'` |
| Metadata file | `{cacheDir}metadata.json` |
| Max size | 100 MB (configurable) |
| Eviction policy | LRU (least recently used) |
| Instance | Singleton (`TTSCacheManager.getInstance()`) |

### Cache Metadata Per Entry

```typescript
interface CacheMetadata {
  key: string;
  uri: string;
  size: number;
  createdAt: number;
  lastAccessedAt: number;
  accessCount: number;
  voice: string;
  engine: 'expo' | 'microsoft';
  text: string;    // First 100 chars (debug only)
}
```

### API

```typescript
// Check cache
const uri = await ttsCacheManager.get(cacheKey);  // null if miss

// Store in cache (called by TTSAudioGenerator after generation)
await ttsCacheManager.set(cacheKey, uri, sizeBytes, metadata);

// Get cache statistics
const stats = await ttsCacheManager.getStats();
// { size, itemCount, hitRate, hits, misses }

// Generate cache key
const key = ttsCacheManager.generateKey(text, voiceSettings);
```

### Eviction

When `currentCacheSize + newFileSize > maxCacheSize`, the manager evicts LRU entries until there is enough space. Metadata is updated on each access to maintain access timestamps.
